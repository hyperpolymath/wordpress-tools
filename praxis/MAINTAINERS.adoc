=== Becoming a Maintainer

WP Praxis uses the *Tri-Perimeter Contribution Framework (TPCF)* for
graduated access.

==== Path to Component Maintainer (Perimeter 2)

*Criteria*: 1. *Expertise*: Demonstrated deep knowledge of the component
2. *Contributions*: 10+ merged PRs in the component area 3.
*Consistency*: 6+ months of regular contribution 4. *Review
Participation*: Actively reviews others’ PRs 5. *Community*: Helps
others in discussions and issues 6. *Alignment*: Shows alignment with
project values

*Responsibilities*: - Review and approve PRs for your component -
Maintain component documentation - Triage issues for your component -
Mentor new contributors - Coordinate with other component maintainers -
Participate in architectural discussions

*Benefits*: - Direct commit access to development branches - Listed on
MAINTAINERS.md - Vote on component-specific decisions - Invitation to
maintainer meetings (when established)

==== Path to Core Maintainer (Perimeter 1)

*Criteria* (tentative, not yet established): 1. *Component Maintainer*
for 12+ months 2. *Cross-Component Knowledge*: Understanding of multiple
components 3. *Leadership*: Mentored other contributors 4. *Governance*:
Participated in major decisions 5. *Trust*: Demonstrated judgment and
responsibility 6. *Availability*: Committed to long-term project health

*Additional Responsibilities*: - Release management - Security incident
response - Roadmap planning - Conflict resolution - Budget decisions (if
applicable)

=== Maintainer Responsibilities

==== All Maintainers

* ✅ Follow the link:CODE_OF_CONDUCT.md[Code of Conduct]
* ✅ Review PRs promptly (within 1 week)
* ✅ Be responsive to issues and discussions
* ✅ Maintain component documentation
* ✅ Write clear commit messages
* ✅ Test changes before merging
* ✅ Coordinate with other maintainers
* ✅ Mentor new contributors

==== Code Review Standards

When reviewing PRs, check for:

[arabic]
. *Functionality*: Does it work as intended?
. *Tests*: Are there tests? Do they pass?
. *Documentation*: Are docs updated?
. *Code Quality*: Follows language standards?
. *Security*: No security vulnerabilities?
. *Breaking Changes*: Are they justified and documented?
. *Performance*: No significant regressions?
. *Accessibility*: UIs are accessible?

==== Merge Criteria

PRs should only be merged when:

* ✅ All CI checks pass
* ✅ At least one approving review
* ✅ No unresolved conversations
* ✅ Tests cover new functionality
* ✅ Documentation is updated
* ✅ CHANGELOG.md is updated
* ✅ Follows contributing guidelines

==== Communication

Maintainers are expected to:

* *Be Responsive*: Reply to mentions within 48 hours
* *Be Transparent*: Explain decisions publicly
* *Be Respectful*: Follow Code of Conduct
* *Be Patient*: Help beginners learn
* *Be Collaborative*: Seek consensus on major decisions

Maintainers can step down at any time:

[arabic]
. *Notify*: Email other maintainers or open an issue
. *Transition*: Help find/train a replacement (if possible)
. *Remove Access*: Maintainer permissions will be revoked
. *Alumni Status*: Listed as "`Emeritus Maintainer`" if desired
